# CAN · LIN 통신

차 한 대에는 엔진 ECU, 브레이크 ECU, 계기판, 윈도우 모터 등 수십 개의 작은 컴퓨터가 들어 있다. 이들을 각각 1:1로 전선을 연결하면 엄청난 수의 와이어가 필요해지고 무게와 비용이 치솟는다. 대신 자동차는 몇 개의 전선만으로 여러 ECU가 함께 메시지를 주고받는 버스(bus) 방식을 쓴다. 앞서 배운 임베디드 SW 위에서, 이제는 "그 소프트웨어가 어떻게 다른 ECU와 데이터를 주고받는가"를 다룬다. 가장 널리 쓰이는 두 프로토콜이 CAN과 LIN이다.

## 학습 목표

- CAN 버스가 어떻게 여러 ECU를 하나의 전선 쌍으로 연결하는지 이해한다.
- CAN의 메시지 ID, 우선순위, 중재(arbitration) 방식을 설명할 수 있다.
- CAN 프레임의 기본 구성 요소를 이해한다.
- LIN 버스가 CAN과 비교해 어떤 용도로, 왜 저비용으로 쓰이는지 설명할 수 있다.

## CAN 버스의 기본 동작

CAN(Controller Area Network)은 두 가닥의 전선(CAN High, CAN Low)으로 여러 ECU를 하나의 네트워크에 묶는 차동 신호(differential signal) 방식의 버스다. 차동 신호를 쓰는 이유는 전기적 잡음에 강하기 때문인데, 두 선의 전압 차이로 신호를 판단하므로 외부 잡음이 두 선에 동시에 섞여도 그 차이는 거의 변하지 않는다.

CAN 버스에는 중앙 관리자가 없다. 모든 ECU가 같은 버스에 메시지를 올리고, 누구나 그 메시지를 들을 수 있다(브로드캐스트 방식). 두 ECU가 동시에 메시지를 보내려 하면 충돌이 생길 수 있는데, CAN은 이를 메시지 ID의 우선순위로 해결한다. ID 값이 낮을수록(비트가 더 많이 0일수록) 우선순위가 높다. 두 메시지가 동시에 전송을 시작하면, 버스는 낮은 ID를 가진 메시지를 그대로 흘려보내고 높은 ID 쪽은 자동으로 전송을 멈추고 양보한다. 이 과정을 중재(arbitration)라 하며, 데이터가 전혀 손실되지 않는다는 점이 CAN의 큰 장점이다. 예를 들어 에어백 관련 메시지는 ID를 낮게 설정해 다른 메시지보다 항상 먼저 버스를 차지하게 설계한다.

## CAN 프레임의 구성

표준 CAN 프레임(CAN 2.0A)은 크게 다음 요소로 이루어진다.

- 식별자(ID): 11비트(표준) 또는 29비트(확장)로, 메시지의 종류와 우선순위를 나타낸다.
- 제어 필드: 데이터 길이(DLC, 0 ~ 8바이트)를 담는다.
- 데이터 필드: 실제 전달할 값, 최대 8바이트.
- CRC: 전송 중 오류가 있었는지 검사하는 체크섬.
- ACK 슬롯: 정상적으로 수신한 노드가 확인 응답을 보내는 비트.

고속 CAN은 보통 500 kbps, CAN FD(Flexible Data-rate)는 더 긴 데이터 필드와 더 빠른 전송 속도(최대 수 Mbps)를 지원해 점점 더 많이 쓰이고 있다.

## LIN 버스: 저비용 보조 네트워크

LIN(Local Interconnect Network)은 CAN보다 훨씬 단순하고 저렴한 네트워크다. 전선 한 가닥(단선)으로 통신하며, 속도도 보통 19.2 kbps 수준으로 CAN보다 느리다. 구조도 다르다. CAN은 모든 노드가 평등하게 버스를 쓸 수 있지만, LIN은 마스터-슬레이브(master-slave) 구조로, 하나의 마스터 노드가 "지금 누가 말할 차례인지"를 스케줄에 따라 지정하고 슬레이브들은 그 지시에만 응답한다.

LIN은 응답 속도나 안전성이 크게 중요하지 않은 부품, 예를 들어 전동 윈도우, 시트 조절, 실내 조명, 와이퍼 모터 제어 같은 곳에 주로 쓰인다. 중요한 제어 신호는 CAN으로, 부가적인 편의 기능은 LIN으로 처리함으로써 전체 네트워크의 비용과 복잡도를 균형 있게 유지한다.

## 정리

CAN과 LIN은 차량 내부의 여러 ECU를 적은 수의 전선으로 연결해 메시지를 주고받게 하는 통신 버스다. CAN은 차동 신호와 ID 기반 중재로 충돌 없이 우선순위 높은 메시지를 먼저 처리하는 강건한 구조를 가지며, 제동·조향 같은 중요한 신호에 쓰인다. LIN은 더 저렴하고 단순한 마스터-슬레이브 구조로, 상대적으로 덜 중요한 편의 기능에 쓰인다. 이런 통신 구조를 바탕으로 여러 ECU가 전체 전장 아키텍처를 이루는데, 이는 다음 단계에서 다룬다.
