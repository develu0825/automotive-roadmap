# 임베디드 SW · RTOS

지금까지 칼만필터와 PID 제어기를 수식으로 설계했다면, 이제는 그 알고리즘을 실제로 차량 안의 작은 컴퓨터, 즉 MCU(Micro Controller Unit) 위에서 돌려야 한다. 문제는 일반 PC와 다르다는 점이다. 브레이크 제어 로직이 5 ms 안에 반드시 끝나야 하고, 그 와중에도 센서 신호를 끊김 없이 받아야 하며, 메모리는 수백 KB 수준으로 제한적이다. 이런 제약 속에서 여러 작업을 안정적으로 동시에 돌리기 위해 실시간 운영체제(RTOS, Real-Time Operating System)를 사용한다. 앞서 배운 상태추정 알고리즘이 실제로 "돌아가는" 환경이 바로 이 장에서 다루는 내용이다.

## 학습 목표

- MCU의 기본 구조(코어, 메모리, 레지스터, 인터럽트)와 펌웨어의 역할을 이해한다.
- RTOS의 태스크, 스케줄링, 우선순위 개념을 설명할 수 있다.
- 세마포어와 뮤텍스가 왜 필요한지, 어떤 문제를 해결하는지 이해한다.
- 실시간 시스템에서 "빠른 것"과 "제시간에 끝나는 것"의 차이를 설명할 수 있다.

## MCU와 펌웨어의 기본 구조

MCU는 CPU 코어, 플래시 메모리(프로그램 저장), RAM(실행 중 데이터), 그리고 센서·구동기와 연결되는 입출력 핀들을 하나의 칩에 모아놓은 장치다. 자동차 ECU 안에는 보통 이런 MCU가 들어 있고, 그 위에서 돌아가는 소프트웨어를 펌웨어(firmware)라 부른다. 펌웨어는 레지스터(register)라는 특정 메모리 주소에 값을 쓰거나 읽어서 하드웨어를 직접 제어한다. 예를 들어 특정 레지스터에 1을 쓰면 LED가 켜지고, 다른 레지스터를 읽으면 ADC(아날로그-디지털 변환기)가 측정한 센서 전압 값을 얻는다.

인터럽트(interrupt)는 CPU가 하던 일을 잠시 멈추고 긴급한 이벤트를 먼저 처리하게 하는 메커니즘이다. 예를 들어 CAN 메시지가 도착하면 인터럽트가 발생해, CPU는 현재 작업을 잠깐 미뤄두고 메시지를 수신 버퍼에 담는 짧은 루틴(인터럽트 서비스 루틴, ISR)을 실행한다.

## RTOS: 태스크와 스케줄링

RTOS는 여러 작업(태스크, task)을 "동시에" 도는 것처럼 보이게 관리하는 소프트웨어 계층이다. 실제로는 CPU 코어 하나가 매우 짧은 시간 단위로 태스크를 번갈아 실행하며, 이를 스케줄링(scheduling)이라 한다. 자동차용 임베디드 시스템에서 가장 흔한 방식은 우선순위 기반 선점형 스케줄링(priority-based preemptive scheduling)이다. 각 태스크에 우선순위를 부여하고, 더 높은 우선순위의 태스크가 준비되면 지금 돌고 있는 낮은 우선순위 태스크를 즉시 멈추고(선점) 먼저 실행한다.

예를 들어 "브레이크 제어" 태스크는 우선순위를 가장 높게, "계기판 디스플레이 갱신" 태스크는 낮게 설정한다. 1 ms마다 브레이크 제어가 돌아야 하고, 디스플레이는 100 ms마다 돌아도 충분하기 때문이다. 이렇게 주기와 우선순위를 설계하는 일을 태스크 스케줄 설계라 한다.

## 동기화: 세마포어와 뮤텍스

여러 태스크가 같은 자원(예: 공유 변수, 센서 버퍼)에 동시에 접근하면 데이터가 꼬일 수 있다. 세마포어(semaphore)는 "지금 자원을 쓸 수 있는 개수"를 세어가며 접근을 조율하는 신호 도구이고, 뮤텍스(mutex, mutual exclusion)는 한 번에 딱 하나의 태스크만 자원에 접근하도록 잠그는 도구다. 예를 들어 센서 인터럽트가 새 값을 버퍼에 쓰는 동안 제어 태스크가 같은 버퍼를 읽으면 값이 섞일 수 있으므로, 뮤텍스로 접근을 순서대로 보장한다. 우선순위가 다른 태스크들이 뮤텍스를 두고 경쟁하면 우선순위 역전(priority inversion) 문제가 생길 수 있어, RTOS는 우선순위 상속(priority inheritance) 같은 기법으로 이를 보완한다.

## 실시간성: 빠른 것과 제시간에 끝나는 것

실시간 시스템에서 중요한 것은 평균적으로 빠른 속도가 아니라, 정해진 시간(데드라인) 안에 반드시 끝난다는 보장이다. 이를 결정성(determinism)이라 하며, 이 보장이 무너지면 하드 리얼타임 시스템(브레이크, 에어백 등)에서는 치명적인 결과로 이어질 수 있다. 엔지니어는 각 태스크가 최악의 경우 얼마나 걸리는지(WCET, Worst-Case Execution Time)를 분석해, 모든 태스크가 데드라인 안에 끝날 수 있는지 스케줄링 가능성을 검증한다.

## 정리

임베디드 SW와 RTOS는 제어·추정 알고리즘을 제한된 자원과 엄격한 시간 제약 속에서 실제로 동작시키는 소프트웨어 기반이다. MCU는 레지스터와 인터럽트로 하드웨어를 직접 다루고, RTOS는 우선순위 기반 스케줄링으로 여러 태스크를 조율하며, 세마포어와 뮤텍스는 공유 자원 접근을 안전하게 만든다. 핵심은 "평균적으로 빠름"이 아니라 "데드라인 안에 항상 끝남"이라는 결정성이며, 이 바탕 위에서 다음 단계인 ECU 간 통신(CAN·LIN)이 이루어진다.
